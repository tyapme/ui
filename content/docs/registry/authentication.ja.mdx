---
title: 認証
description: プライベートおよびパーソナライズされたコンポーネントのために認証でレジストリを保護する。
---

認証を使うと、プライベートレジストリの運用、コンポーネントへのアクセス制御、チームやユーザーごとに異なるコンテンツの提供が可能になります。このガイドでは一般的な認証パターンとそのセットアップ方法を紹介します。

認証によって次のユースケースが実現できます：

- **プライベートコンポーネント**: ビジネスロジックや社内コンポーネントを保護する
- **チーム固有のリソース**: チームごとに異なるコンポーネントを提供する
- **アクセス制御**: 機密コンポーネントや試験的コンポーネントの閲覧を制限する
- **利用状況分析**: 組織内で誰がどのコンポーネントを使っているか把握する
- **ライセンス管理**: プレミアムまたはライセンス付きコンポーネントの利用者を管理する

## 一般的な認証パターン

### トークンベース認証

最も一般的なアプローチは Bearer トークンや API キーを使う方法です：

```json title="components.json"
{
  "registries": {
    "@private": {
      "url": "https://registry.company.com/{name}.json",
      "headers": {
        "Authorization": "Bearer ${REGISTRY_TOKEN}"
      }
    }
  }
}
```

トークンを環境変数に設定します：

```bash title=".env.local"
REGISTRY_TOKEN=your_secret_token_here
```

### API キー認証

一部のレジストリではヘッダーに API キーを使います：

```json title="components.json"
{
  "registries": {
    "@company": {
      "url": "https://api.company.com/registry/{name}.json",
      "headers": {
        "X-API-Key": "${API_KEY}",
        "X-Workspace-Id": "${WORKSPACE_ID}"
      }
    }
  }
}
```

### クエリパラメータ認証

シンプルな構成ではクエリパラメータを使います：

```json title="components.json"
{
  "registries": {
    "@internal": {
      "url": "https://registry.company.com/{name}.json",
      "params": {
        "token": "${ACCESS_TOKEN}"
      }
    }
  }
}
```

これにより `https://registry.company.com/button.json?token=your_token` のような URL が生成されます。

## サーバー側の実装

レジストリサーバーに認証を追加する方法を示します：

### Next.js API ルートの例

```typescript title="app/api/registry/[name]/route.ts"
import { NextRequest, NextResponse } from "next/server"

export async function GET(
  request: NextRequest,
  { params }: { params: { name: string } }
) {
  // Authorization ヘッダーからトークンを取得する。
  const authHeader = request.headers.get("authorization")
  const token = authHeader?.replace("Bearer ", "")

  // クエリパラメータからも取得できる。
  const queryToken = request.nextUrl.searchParams.get("token")

  // トークンが有効か確認する。
  if (!isValidToken(token || queryToken)) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
  }

  // トークンがこのコンポーネントにアクセスできるか確認する。
  if (!hasAccessToComponent(token, params.name)) {
    return NextResponse.json({ error: "Forbidden" }, { status: 403 })
  }

  // コンポーネントを返す。
  const component = await getComponent(params.name)
  return NextResponse.json(component)
}

function isValidToken(token: string | null) {
  // ここにトークン検証ロジックを追加する。
  // データベース照合、JWT 検証など。
  return token === process.env.VALID_TOKEN
}

function hasAccessToComponent(token: string, componentName: string) {
  // ここにロールベースのアクセス制御を追加する。
  // トークンが特定コンポーネントにアクセスできるか確認する。
  return true // 実際のロジックを記述する。
}
```

### Express.js の例

```javascript title="server.js"
app.get("/registry/:name.json", (req, res) => {
  const token = req.headers.authorization?.replace("Bearer ", "")

  if (!isValidToken(token)) {
    return res.status(401).json({ error: "Unauthorized" })
  }

  const component = getComponent(req.params.name)
  if (!component) {
    return res.status(404).json({ error: "Component not found" })
  }

  res.json(component)
})
```

## 高度な認証パターン

### チームベースのアクセス

チームごとに異なるコンポーネントを提供します：

```typescript title="api/registry/route.ts"
async function GET(request: NextRequest) {
  const token = extractToken(request)
  const team = await getTeamFromToken(token)

  // このチームのコンポーネントを取得する。
  const components = await getComponentsForTeam(team)
  return NextResponse.json(components)
}
```

### ユーザーパーソナライズレジストリ

ユーザーの設定に基づいたコンポーネントを提供します：

```typescript
async function GET(request: NextRequest) {
  const user = await authenticateUser(request)

  // ユーザーのスタイルとフレームワークの設定を取得する。
  const preferences = await getUserPreferences(user.id)

  // パーソナライズされたコンポーネントバージョンを取得する。
  const component = await getPersonalizedComponent(params.name, preferences)

  return NextResponse.json(component)
}
```

### 一時アクセストークン

セキュリティ強化のために有効期限付きトークンを使います：

```typescript
interface TemporaryToken {
  token: string
  expiresAt: Date
  scope: string[]
}

async function validateTemporaryToken(token: string) {
  const tokenData = await getTokenData(token)

  if (!tokenData) return false
  if (new Date() > tokenData.expiresAt) return false

  return true
}
```

## マルチレジストリ認証

[名前空間レジストリ](/docs/registry/namespace)を使うと、異なる認証を持つ複数のレジストリをセットアップできます：

```json title="components.json"
{
  "registries": {
    "@public": "https://public.company.com/{name}.json",
    "@internal": {
      "url": "https://internal.company.com/{name}.json",
      "headers": {
        "Authorization": "Bearer ${INTERNAL_TOKEN}"
      }
    },
    "@premium": {
      "url": "https://premium.company.com/{name}.json",
      "headers": {
        "X-License-Key": "${LICENSE_KEY}"
      }
    }
  }
}
```

これにより次のことが可能です：

- パブリックとプライベートのレジストリを混在させる
- レジストリごとに異なる認証を使う
- アクセスレベルでコンポーネントを整理する

## セキュリティのベストプラクティス

### 環境変数を使う

トークンをバージョン管理にコミットしないでください。常に環境変数を使ってください：

```bash title=".env.local"
REGISTRY_TOKEN=your_secret_token_here
API_KEY=your_api_key_here
```

`components.json` で参照します：

```json
{
  "registries": {
    "@private": {
      "url": "https://registry.company.com/{name}.json",
      "headers": {
        "Authorization": "Bearer ${REGISTRY_TOKEN}"
      }
    }
  }
}
```

### HTTPS を使う

転送中のトークンを保護するため、レジストリには常に HTTPS URL を使ってください：

```json
{
  "@secure": "https://registry.company.com/{name}.json" // ✅
  "@insecure": "http://registry.company.com/{name}.json" // ❌
}
```

### レート制限を追加する

レジストリの不正利用を防ぎます：

```typescript
import rateLimit from "express-rate-limit"

const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15分
  max: 100, // IP ごとに windowMs 内で最大 100 リクエスト
})

app.use("/registry", limiter)
```

### トークンをローテーションする

アクセストークンを定期的に変更します：

```typescript
// 有効期限付きの新しいトークンを作成する。
function generateToken() {
  const token = crypto.randomBytes(32).toString("hex")
  const expiresAt = new Date(Date.now() + 30 * 24 * 60 * 60 * 1000) // 30日。

  return { token, expiresAt }
}
```

### アクセスをログに記録する

セキュリティと分析のためにレジストリアクセスを追跡します：

```typescript
async function logAccess(request: Request, component: string, userId: string) {
  await db.accessLog.create({
    timestamp: new Date(),
    userId,
    component,
    ip: request.ip,
    userAgent: request.headers["user-agent"],
  })
}
```

## 認証のテスト

認証済みレジストリをローカルでテストします：

```bash
# curl でテストする。
curl -H "Authorization: Bearer your_token" \
  https://registry.company.com/button.json

# CLI でテストする。
REGISTRY_TOKEN=your_token npx shadcn@latest add @private/button
```

## エラーハンドリング

shadcn CLI は認証エラーを適切に処理します：

- **401 Unauthorized**: トークンが無効または未指定
- **403 Forbidden**: トークンにこのリソースへのアクセス権限がない
- **429 Too Many Requests**: レート制限を超過した

### カスタムエラーメッセージ

レジストリサーバーはレスポンスボディにカスタムエラーメッセージを返すことができ、CLI がユーザーに表示します：

```typescript
// レジストリサーバーがカスタムエラーを返す
return NextResponse.json(
  {
    error: "Unauthorized",
    message:
      "Your subscription has expired. Please renew at company.com/billing",
  },
  { status: 403 }
)
```

ユーザーには次のように表示されます：

```txt
Your subscription has expired. Please renew at company.com/billing
```

状況に応じた案内を提供できます：

```typescript
// 状況ごとに異なるエラーメッセージ
if (!token) {
  return NextResponse.json(
    {
      error: "Unauthorized",
      message:
        "Authentication required. Set REGISTRY_TOKEN in your .env.local file",
    },
    { status: 401 }
  )
}

if (isExpiredToken(token)) {
  return NextResponse.json(
    {
      error: "Unauthorized",
      message: "Token expired. Request a new token at company.com/tokens",
    },
    { status: 401 }
  )
}

if (!hasTeamAccess(token, component)) {
  return NextResponse.json(
    {
      error: "Forbidden",
      message: `Component '${component}' is restricted to the Design team`,
    },
    { status: 403 }
  )
}
```
